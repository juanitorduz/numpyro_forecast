# numpyro_forecast v0.2 — Execution Plan (roadmap v3)

Executes `numpyro_forecast_roadmap_v3.md` sequentially in this workspace, **one commit per unit (P0–P18)**, no PRs. Each commit must pass `prek run --all-files`, `uv run ty check numpyro_forecast/`, and `uv run pytest` before moving on. Roadmap section numbers (§) are the normative spec for bodies, error messages, and docstrings; this plan pins the sequencing and the repo-specific deltas.

## Current state vs roadmap (deltas that shape the work)

- Core exists in `numpyro_forecast/functional.py`: `fit_svi` (guide/optim as narrow types, plus `num_particles`/`progress_bar` not in the roadmap signature), `fit_mcmc` (NUTS hardcoded), `SVIFit` (no `data`/`covariates`), `MCMCFit` (no `num_chains`), `_draw_posterior_impl` singledispatch, `forecast` (no chunk padding), `predict_in_sample`.
- `numpyro_forecast/util.py` has `shift_loc`/`slice_time`/`prefix_condition` but no elementwise registry, no `require()`.
- Missing entirely: `convert.py`, `contrib/`, `spikes/`, `resolve_*` functions, `markov_time_series`, `predict_glm`, `backtest_vectorized`, `results_to_dataframe`, new metrics, `count_compilations` fixture, and all new test files.
- **Spikes:** only `spike_vmap_svi.py` exists (repo root, executed GREEN on jax 0.10.2 / numpyro 0.21.0, which matches the installed venv). `spike_scan_replay.py` (S-M) is missing and must be recreated and executed in P0 before Phase 3.
- **arviz is already a hard dep** (`arviz>=1.2`, ArviZ 1.0 line; `arviz-base`/`xarray` in `uv.lock`), so `to_datatree` needs no lazy-import gating. The `to_inferencedata` legacy shim (classic arviz <1.0) conflicts with this hard pin; handled in P12 (shim raises actionable ImportError when classic arviz is absent; legacy CI leg deferred).
- Existing public kwargs `num_particles`/`progress_bar` on `fit_svi` and `progress_bar` on `fit_mcmc` are **kept** (additive change only; roadmap signatures gain `stable_update`, `optim`/`guide` widening, `kernel`/`kernel_kwargs`/`chain_method`).

- **P4 (§4.1) walltime fix.** `evaluate.py`: `_timed` gains `jax.block_until_ready(result)`; add `_block_object` (pytree over `vars(obj)`, slots-safe no-op); wrap training timing. - **P5 (§4.2) chunk padding.** `functional.py`: `_pad_posterior(posterior, batch_size)` with three ValueError guards; revised chunk loop in `forecast` (pad → per-chunk split keys → concat → slice `[:num]`); PRNG-semantics note on `forecast` docstring. - **P6 (§6.1) elementwise registry.** `util.py`: `_ELEMENTWISE_FAMILIES`/`_ELEMENTWISE_CHECKED` sets, `register_elementwise` (exact-type membership, decorator-usable), `_check_elementwise` (event_shape `()` + params broadcast vs batch_shape, cached); rewrite generic `slice_time` (membership → check → slice) and `prefix_condition` (membership → `slice_time(d, slice(t, None))`, the R1 fix); new `shift_loc` registrations Laplace/Cauchy/AsymmetricLaplace/Gumbel; register elementwise at import: Normal, StudentT, Laplace, Cauchy, AsymmetricLaplace, Gumbel, Poisson, NegativeBinomial2. Export `register_elementwise` from `__init__.py`. Tests (`tests/test_util.py` + new `tests/test_consistency.py`): shift identity over all families incl. `Independent(Laplace)`, per-family slice vs manual, Poisson prefix == future marginal, Dirichlet actionable error, decorator registration, subclass non-inheritance, structural-fake failure, **`test_registry_consistency` (I4)**.
